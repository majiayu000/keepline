# 后续走查协议，本轮未执行

目的：判断哪一项功能值得进入实现；不比较模型答题能力，也不要求用户批准自动化操作。

客群假设为多会话个人开发者；先观察现有工具，再展示原型。5 人只算小样本探索，不代表市场。

| 场景 | 任务 | 记录 | 失败条件 |
|---|---|---|---|
| 等待输入 | 5 个会话中有一个真实等待、一个后台子任务仍在运行 | 找到等待事项时间、误报、点错会话 | 输入送错会话，或把仍在执行的工作标成可交付 |
| 检查结果 | 3 个任务中包含一项失败检查或过期检查 | 核对时间、遗漏、打开工具数、能否找回来源 | 误把过期/别的 commit 的检查当这轮证据 |
| 并行开工 | 在同一仓库建立两项独立工作并运行服务 | 环境准备时间、端口冲突、改动归属 | 覆盖已有改动，自动泄露配置，或无法识别服务归属 |
| 次日接手 | 隔一天回到其中两项工作 | 找回决定与下一步耗时、是否需重读全部记录 | 恢复到错误目录、错误 session 或误称保留了已死亡进程 |
| 断连恢复 | 关闭界面后重开；另做后台退出用例 | PID/会话对应、未发送草稿、重复执行 | 自动重发结果未知的输入，或丢掉未发送反馈 |

对照用户惯用工具与 Keepline 当前构建/原型；保存构建身份、任务和授权范围。工具顺序轮换，任务难度匹配。原型演示与真实运行验收单列。没有用户提供环境与任务前不执行这些用例，不进行陌生竞品线上服务测试。

继续门槛与停止条件只在 [功能建议](../02-my-plan.md) 保存。本协议只说明怎么测。
