# 任务结果核对页：一项真实变更的原型

[打开交互原型](index.html) · [亮色截图](desktop.png) · [深色截图](desktop-dark.png) · [窄屏截图](mobile.png)

样本为本地提交 `56522392d27d975924af77dd3595026e4a0cc981`，只涉及 keeplined 文件描述符上限。提交说明作为工作目标，不冒充用户原话；不归属工作区其他修改。

采用：把任务目标、固定 diff、验证输出、未验项与反馈放到同一页，作为下一轮真人走查的原型。待验证：是否比用户现有流程省时、减少遗漏，以及是否值得接入原生 App。

## 已观测到的内容

- 从固定提交逐字提取的 `raise_open_file_limit()` 在独立子进程执行，soft 上限由 256 提高到 65536，再次调用后保持不变；没有启动或重启现有 App/daemon。[原始实测记录](probe-evidence.json) 与 [函数验证程序](fd-limit-probe.rs)。
- 页面可以打开原始证据、查看固定 diff、切换来源页，并把未验事项写入反馈。
- 编辑后的反馈在切换页签、重新加载后完整保留。阅读勾选仅记录阅读，不变成任务验收。
- 实际看过亮色、深色与 390px 窄屏截图。浏览器观察到没有横向溢出和脚本异常。[走查记录](browser-check.json) 与 [可重跑浏览器检查](browser-check.mjs)。
- 隔离浏览器拒绝剪贴板写入时，页面会选中反馈并提示用快捷键复制；本轮没有证实真实系统剪贴板写入。

## 没验的内容

没有启动真实 50+ 终端场景，没有验 Finder 启动或后台更新，没有读取该提交的远端 CI。函数通过不能证明这些场景通过。

原型没有关联原 Agent，会明确说明并让用户复制反馈；没有发送指令，没有修改原生 App。没有外部用户参与，因此没有节省时间、留存或付费结论，不能把代理走查称为用户验证。

当前样本只有一个真实任务。后续仍需覆盖检查过期、验证失败、同目录混改等相邻情况；本轮未将它们伪装成真实数据。

## 可执行的观察

让用户打开原型后回答三件事：这项工作改了什么、证据能证明到哪里、下一步要补什么。再让用户留下反馈并重新打开检查草稿。记录时间与遗漏，与用户惯用的 git/终端流程轮换对照。继续与停止门槛沿用[用户走查协议](../eval/user-observation-protocol.md)。

已验：亲眼看到真实函数输出、来源对话框、草稿重开保留及深浅色截图。没验：原生集成和真人效率。相邻情况：窄屏已验；失败/过期检查样本未验。
