Keepline next 架构与状态机

next/ 是一个 Rust workspace：keeplined 宿主持有全部终端和识别逻辑，keepline-app 是 GPUI 桌面工作台，两者只通过 workbench.sock 说话；手机经 keepline-relay 远程连同一个宿主。所有状态都存在宿主的 Workspace 里，界面上的分组是从它派生出来的，不另存。

1 · 系统总图

三个进程：Agent CLI 跑在宿主开的 PTY 里；宿主从四路读信号；工作台和手机都只是宿主的观看者和遥控器。

  1. Agent 跑在宿主的 PTY 里，键盘输入和屏幕字节都经过 pty.rs。PATH 带着 keeplined，终端里的 Agent 也能调 keeplined list / split（虚线）。
  2. CLI 写对话日志，FSEvents 通知宿主增量读；中途丢事件就从检查点补扫。
  3. CLI 自带的 Hook 运行 "$KEEPLINE_HOOK" hook --agent …，靠 KEEPLINE_TERMINAL 指明是哪个终端。
  4. 只在需要确认「还在等吗」时调一次 claude agents --json，从不定时轮询。
  5. 识别层产出的信号都汇到 content/，改的是一张 Content 卡片上的 turn，再写回 Workspace。
  6. 终端画面（VT 快照 + 增量帧）直接从 live 推给观看者，不经 SQLite。
  7. 工作台订阅 Workspace 的每次 revision；它的所有改动都以 Edit 请求发回宿主。
  8. 远程会话跑在 Noise 通道里，中继看不到内容。

2 · 一个信号怎么变成你看到的状态

六路信号，只有一张卡片。回合状态由信号改，结局只由你改；界面上的分组、圆点和通知都是 Workspace 的派生结果。

4 · 终端进程 ProcessState

一个 Terminal 是一个 PTY，它的 shell 可以先后跑很多段对话。关掉窗格不等于结束：PTY 身份和摆放位置是分开的。

在跑等待 / 过渡正常结束出错 / 中断中性由你决定双边框 = 终态

5 · 回合 Turn

核心状态机。每次变化由 settle() 记下是哪路信号定的（日志 / Hook / 画面 / 官方状态 / 子 Agent），进入 Waiting 时 waiting_episode += 1，同一个对话框被多路信号报到只算一次通知。任何状态收到新的用户发话都回到 Running。

在跑等待 / 过渡正常结束出错 / 中断中性由你决定双边框 = 终态

6 · 结局 Outcome：做没做完由你定

Agent 说「完成了」只记成 completed_claim，不改结局。一轮停了就是「等你验收」，只有你点「标记完成」才进 Completed。

在跑等待 / 过渡正常结束出错 / 中断中性由你决定双边框 = 终态

7 · 分组：从状态派生，先命中先算

分组不存储，每次渲染从 Outcome + Turn + 终端状态现算。左边用于收件箱和看板列，右边用于 Keepline 终端里正活着的 Agent（侧栏圆点、窗格）。

收件箱 · Content::group

  1. 结局是 Completed 或 Abandoned→做完了
  2. 结局是 Deferred 且没到期→稍后再看
  3. 没在跑，且距上一轮（或上次验收/到期）超过 stale_days 天→很久没动
  4. turn = Waiting→等你回答
  5. turn = Error，或所在终端 Failed / Interrupted / 退出码 ≠ 0→出错了
  6. turn = Completed，是当前对话，后台还有子 Agent / 监视 / 定时唤醒→在跑
  7. turn = Completed（不管 Agent 说没说完成）→等你验收
  8. turn = Running，且是当前对话或 15 分钟内有更新→在跑
  9. 其余（Interrupted、Unknown、日志里的 Running 已过期）→停下了

活着的窗格 · sidebar_status

  1. turn = Running，或 Completed 但子 Agent 还在跑→Working · 在跑
  2. turn = Waiting→Waiting · 等你回答（要你注意）
  3. Idle 且还没开始第一轮（没提问、turn = Unknown）→Fresh · 新开的
  4. Idle 且结局 Completed→Closed · 做完了
  5. Idle 且 turn = Error→Error · 出错了（要你注意）
  6. Idle 且后台有 shell / 监视 / 定时唤醒→Background · 等后台
  7. Idle，这一轮在你没看着时停的→Done · 等你验收（要你看一眼）
  8. Idle，其余→Ready · 等你验收

「没看着时停的」由 track_unseen 记：Phase 从非 Idle 变 Idle 且窗格没显示，就标为未看；显示出来或再动起来就清掉。

8 · 对话绑定

对话身份是 (runtime, cli_session_id)，和 PTY、摆放位置都无关。宿主尝试 CLI 提供的每种证据，有歧义宁可不绑。

在跑等待 / 过渡正常结束出错 / 中断中性由你决定双边框 = 终态

9 · 识别健康 RecognitionPhase

没有轮询兜底：日志全靠 FSEvents。丢事件时按目录子树补扫，补扫范围先持久化。

10 · 远程 RemoteState

keeplined remote --relay 主动连出去，状态经 RemoteReport 报给宿主再给 app。

11 · 宿主升级交接

app 发现正在跑的宿主和自己带的不是同一份代码（digest 不同），就启动新宿主接管。终端里的 shell 和 Agent 不会察觉。
