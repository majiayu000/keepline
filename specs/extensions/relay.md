# 自建中继：手机在哪都能连上机器

状态：第一版完成，结论「采用」（2026-11-01）；同一天加上了按设备分权限。

用户 11-01 的要求：
- 自己写一个 Rust 中继，不用 iroh，也不嵌进 App；
- 协议沿用 alma-relay（yetone，MIT）的 WebSocket 部分，换中继时不用改代码。

## 要支撑的决定

这一版要回答一个问题：手机经过一台只转发密文的中继，能不能像 `remote --stdio` 一样看画面、打字，而且不拖慢工作台和别的手机。

能的话，手机 App 只要会两件事：WebSocket 和 Noise 加密（各平台都有现成的库）。

## 结构

```
keeplined remote --relay URL ──主动连出 WSS /agent──▶ keepline-relay（或 alma-relay）◀── WSS /c/<令牌>/keepline ── 手机
        │ 每个手机一个会话：remote::serve，和 --stdio 同一套协议                                  │
        └──────────── Noise 握手和加密都在两端完成，中继只转发密文 ─────────────────────────────┘
```

| 部分 | 位置 | 说明 |
|---|---|---|
| 共用库 | `next/crates/keepline-remote` | 纯逻辑：不用 tokio，不碰网络和文件。有五块：`protocol` 协议消息的类型、`role` 权限档、`link` 配对链接、`secure` 加密通道、`wire` 和中继之间的帧。电脑端、中继、以后的桌面工作台都用它 |
| 测试向量 | `keepline-remote/vectors/v1.json` | 固定输入和它们必须得到的字节：令牌、令牌哈希、预共享密钥、两条握手消息、三条加密消息、一个中继帧、配对链接。别的语言实现完逐字节对照。字节一变，`tests/vectors.rs` 就失败 |
| 中继 | `next/crates/keepline-relay`（二进制 `keepline-relay`，2.5 MB） | tokio 加 axum。只做 WebSocket 隧道，不做 HTTP 隧道、APNs 和 TURN |
| 线协议 | `keepline_remote::wire` | 和 alma-relay 一致：`register`/`registered`、`wopen`/`wopened`/`werr`/`wmsg`/`wclose`，以及协议 2 的二进制帧 `[类型][id 长度][id][内容]`。中继只认 `sha256(令牌)` |
| 机器端 | `keeplined/src/relay.rs`、`devices.rs` | 主动连中继，断了就重连（1 秒起，每次翻倍，最多 30 秒）。每个手机开一个 `remote::serve`。在这里检查权限、保存设备、记日志 |
| 参考客户端 | `keepline-relay/examples/phone.rs` | 几十行的终端版「手机」：标准输入写请求，标准输出出回复。写 App 时照着它做 |

权限只在电脑端检查。中继和手机都不可信，所以不放在这两处。

## 配对、权限和加密

两样秘密，都存在运行目录里，权限 0600：
- **机器码**（`remote-code`）：一台机器的所有手机共用。
  - 路由令牌由它推出：`base64url(sha256("keepline route 1\0" ‖ 机器码))`。
  - 手机把令牌放进 URL，中继只保存令牌的哈希。
- **每台手机自己的密钥**（`remote-devices.json`）：作为 Noise 握手的预共享密钥，`sha256("keepline psk 1\0" ‖ 密钥)`。
  - 中继看到的任何东西都推不出它。
  - 每台手机可以单独撤销。

命令：

| 命令 | 作用 |
|---|---|
| `keeplined remote --pair --relay URL --name iPhone --role full` | 配对一台新手机，打印二维码和链接。权限三档：`view` 只看、`answer` 能答审批、`full` 完全控制（默认） |
| `keeplined remote --devices` | 列出手机：编号、名字、权限、配对时间、最近一次连接 |
| `keeplined remote --device <编号或名字> --role answer` | 改权限。它正连着的会话一秒内断开（4401），重连后按新权限 |
| `keeplined remote --revoke <编号或名字>` | 取消配对。它正连着的会话一秒内断开（4401），之后再也连不上 |
| `... --new-code` | 换掉机器码，并清空所有手机 |

配对链接的格式：
```
keepline://pair?v=2&relay=<中继>&code=<机器码>&device=<设备编号>&key=<设备密钥>&machine=<机器 ID>&name=<名字>
```
手机连接的地址是 `/c/<令牌>/keepline?d=<设备编号>`。

权限：
- `hello` 的回复里带上 `role`，`ops` 里只列出这台设备能用的操作。
- 越权的请求返回错误，例如「这台设备的权限是「只看」，不能 keys」，终端收不到任何东西。

日志（`remote-log.jsonl`，0600）：
- 记录连接（connected）、拒绝（refused）、离开（left）、因撤销或改权限断开（dropped）。
- 每一次 send、keys、answer 都记一条：设备、名字、操作、终端，以及失败原因。
- 不记打的内容。
- 超过 4 MiB 时，整个文件挪到 `remote-log.1.jsonl`，覆盖掉更早的那份。`--devices` 两份都读。
- 被拒绝的越权请求不算操作，不记。

- 握手：`Noise_NNpsk0_25519_ChaChaPoly_BLAKE2s`，prologue 为 `keepline remote 1`，由手机先发。
  - 设备编号不认识、或者密钥不对，都完成不了握手。机器对这种连接回 `wclose 4401`，一个字节都不回答。
  - 每次连接都用新的临时密钥，所以有前向保密。
  - 篡改、重放、乱序的消息都解不开。
- 握手之后，每条 WebSocket 二进制消息是一段密文，解开后第一个字节是类型：
  - `0` DATA：远程协议 JSON 行里接下来的字节，可能在任意位置切开，单条最多 32 KiB。
  - `1` ACK：大端 u32，表示「我收下了多少 DATA 字节」。
- **流量控制在两端完成，和用哪个中继无关**：
  - 机器给每个手机最多 1 MiB 没确认的数据。
  - 手机不读了，机器就停止读这个会话；后台会把它看的终端标成跟不上，之后重发一次整屏。
  - 别的手机和工作台都不受影响。

## 中继的行为

| 情况 | 做法 |
|---|---|
| 机器注册 | 10 秒内必须发 `register`。设了 `--key` 或 `RELAY_REGISTRATION_KEY` 时，密钥不对就关闭，代码 4003；令牌哈希格式不对是 4002；满了是 1013 |
| 同一个令牌又注册一次 | 旧的那条收到 4000，`keeplined` 看到 4000 就退出，不来回抢 |
| 手机连一个不在线的机器 | 升级前直接返回 502；路径不对返回 404；一台机器超过 256 个手机返回 503 |
| 机器回 `wopened` 之前手机就发了消息 | 先存着，超过 4 MiB 就关闭，代码 1009 |
| 机器断开 | 它的手机全部关闭，代码 1012，让手机重连 |
| 手机落后超过 16 MiB | 只断开这个手机，代码 1013，并告诉机器。机器的连接照常转发给别的手机 |
| 手机 → 机器 | 发往一台机器的数据最多缓存 8 MiB，超过时手机那边等着，中继内存不会被撑大 |
| 存活检测 | 中继每 25 秒 ping 一次机器，两个周期没有回应就断开；机器每 30 秒 ping 一次，75 秒收不到消息就重连 |
| `/healthz` | `{ok, edition: "keepline", version, protocol: 2, agents}` |

部署：
```bash
keepline-relay --listen 127.0.0.1:8787 [--key 注册密钥]
```
前面放一个 HTTPS 反向代理（Caddy 或 nginx），要允许 WebSocket。

也可以不用自己的中继，改用部署好的 alma-relay（Cloudflare Workers 或 Docker 都行），机器端不用改。

## 验收

| 指标 | 门槛 | 结果 |
|---|---|---|
| 经过中继，按键到画面回显 | ≤ 200 ms | 本机中继，连跑 4 次 20 次按键：p50 0.8–2.5 ms，p95 0.87–4.1 ms |
| 一个手机不读，不拖慢别人 | 旁边手机按键 ≤ 200 ms | 不读的手机停在 1.04 MB（窗口 1 MiB）；旁边手机最慢 1.1–1.8 ms；恢复读取后追到最新画面 |
| 中继层面卡住的手机 | 不拖慢同一台机器的其他手机 | 中继测试：卡住的手机超过上限被断开（1013）；旁边手机往返最慢 1.2–2.5 ms |
| 认证 | 不知道密钥的连接什么都拿不到 | 设备编号对、密钥错的，和没配对过的设备，都被 4401 关闭，一个字节都没收到；Noise 测试覆盖篡改、重放和跨连接重放 |
| 权限 | 只看的设备打不了字 | 只看的设备 `keys` 被拒，终端没收到；`hello` 的 `ops` 里没有 keys；watch 照常能用 |
| 撤销、改权限 | 正在连的会话 ≤ 3 秒断开 | 连跑 5 次：改权限后 0.92–0.93 s、撤销后 0.99 s 收到 4401。改权限后重连拿到新权限；撤销后再连被拒，`--devices` 里也没有它了 |
| 协议类型 | 实际发出的每一行都符合类型 | 端到端测试里，手机收到的每一行都解析成 `protocol::Incoming`；`hello` 和 `list` 解析成 `Hello` 和 `List` |
| 测试向量 | 和另一种实现对得上 | 用 Python hashlib 独立重算：令牌、令牌哈希、预共享密钥、码的文本形式、中继帧，全部一致。Noise 那部分只有 snow 一种实现，没有交叉验证 |
| 日志 | 每次操作都有记录 | 测试核对了 connected、refused、dropped，以及按键那条（设备名、终端、无错误）；越权被拒的请求没有记 |
| 断线恢复 | 中继重启后自动回来 | 端到端测试：中继在同一端口重启后，机器自己重连，手机能再次 hello |
| 空闲开销 | 没有手机时可以忽略 | release 版测 10 秒：机器端和中继 CPU 都是 0.00%，常驻内存 7.9 MB 和 3.4 MB |
| 有手机时的开销 | 低 | 一部手机看 4 个转圈终端（约 525 行）：机器端 0.6–0.8%（加上权限检查后）、中继 0.6%，后台 0.5–0.7% |
| TLS | wss 能用 | 连 `https://example.com`：TLS 握手成功，收到 HTTP 404，然后按 1、2 秒退避重连 |

测试：
- `keepline-relay` 单元测试 7 个，`tests/relay.rs` 4 个（连跑 20 次全过）；
- `keeplined` 端到端测试 `a_phone_on_a_relay_drives_a_terminal_through_a_channel_the_relay_cannot_read`，连跑 4 次全过；
- 测开销的脚本在会话的 scratchpad 里（`relay_cpu.py`）。

**没验**：
- 没和真正的 alma-relay 联调过：本地跑它需要执行外部代码，被权限拦下了。线协议是照它的文档和源码写的。
- 没用真手机、没跨两台机器、没在公网中继上测过延迟。
- iOS 锁屏以后连接会断，要靠推送补上，还没做。

## 放弃条件

- 和 alma-relay 联调时，如果协议不兼容的地方改不动，就放弃兼容，只用自己的中继。机器端协议不变。
- 真手机经过公网中继，按键回显的 p95 超过 300 ms，并且瓶颈在中继本身，就重新考虑直连（iroh）。
