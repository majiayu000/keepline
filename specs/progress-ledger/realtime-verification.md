# 实时更新与增量解析验收

2026-10-07。本轮在 `keepline-realtime` 工作区、`feat/realtime-updates` 分支完成，基于主工作区当时未提交的 UI 改版快照；没有覆盖正在变化的主工作区。以下只描述本轮修复，快照中的 UI、已读记录迁移等属于前置改动。

## 问题与修复

- 服务默认扫描间隔为 60 秒，CLI 和菜单栏行为不一致；改为 5 秒，增加日志目录的文件变化监听。变化事件合并，扫描期间的追加安排下一轮；审批、派发和结束事件保持快速触发。保留周期扫描以核对进程状态及监听失败，关闭周期扫描仍保持原有显式触发语义。停止服务关闭所有监听器。
- 首轮扫描以前先发通知、再解除启动屏障，客户端可能马上读到 503；改为可读取后推送。原来只推 `ledger:update`，会话页收不到其监听的 `sync:complete`；现在同时通知两个页面。
- 详情以前只在 15 秒定时器里更新。详情、列表和回顾现在响应推送及重连，合并短时间的重复事件；保持已打开的详情和编辑状态。鼠标悬停时更新已有内容和新会话，只有列表顺序等候用户移开。
- 新 UI 快照的 `ledger_views` 增加了列，旧位置式 INSERT 会失败；明确写入 `session_id,expires_at`，避免详情查看请求失败。
- 解析缓存保存已处理完整 JSONL 行的字节位置、累计摘要状态和事实配对状态。新扫描进程读取追加部分；CRLF、UTF-8、未完成尾行均按字节保留正确位置。工具结果可以匹配上一轮读取的调用，累计用量保留 Map 状态。文件缩短、inode 替换、同尺寸改写、配置或日窗口变化时重读；首尾校验阻止常见重写后误续读。
- checkpoint 使用现有派生缓存表，不增产品配置或表，不改原始日志。依赖 agent 日志的追加写入契约；不是任意文件编辑器的增量 diff，没有保证检测“同 inode 中部改写并同时增长、首尾不变”的任意变更。
- Bun 测试命令限定 `src/__tests__`，避免把 Playwright 测试交给 Bun 执行。浏览器测试使用严格端口和独立 Vite 实例，禁止悄悄复用另一个项目。

## 后续优化：请求、后台标签页与跨天缓存

- 总览的普通推送只重新读取账本；目标／待办页读取相应关联数据，重连、回到前台、周期核对和用户操作仍同步关联数据。设置只在首次加载、进入设置页及保存时读取／更新，手动“刷新数据”只执行一轮刷新。
- 列表和详情按请求顺序应用结果，过期的响应与错误不会覆盖较新的读取结果；切换会话也使旧详情请求失效。隐藏标签页暂停自动轮询和推送触发的请求，回到前台补齐。
- 账本列表及详情使用私有 HTTP 缓存，`Vary: Authorization`、ETag 和每次重验证保证用户隔离与内容新鲜度。未变化时返回 304，无正文；有变化仍返回该接口完整结果，没有增加逐行 delta 协议。认证、400／404／500 错误路径保持原有契约。
- 显示连接状态和最后成功读取的时间；WebSocket ping 没有 pong 回应时重新连接，正常心跳不重连。
- 日期切换不再单独使日志读取位置失效。跨天追加复用 checkpoint，同时写入新保留窗口的事实缓存；已有事实过期、跨天未知记录统计可能改变、配置变化或文件替换／改写等情况仍重建。旧格式的派生 checkpoint 按新语义重新生成，没有数据迁移或原始日志写入。

当前数据分为三层：Codex／Claude 原始 JSONL；`keepline.db` 中的会话、要求、证据、纠正和验收等结构化数据；`session-summaries-v2.sqlite` 中的摘要、事实、账本派生结果与读取位置。它不是全部原始日志的独立备份。隔离真实数据库检查时有 1,473 个会话，缓存表有 7,151 条派生记录；默认账本保留期为 30 天，默认首页读取最近 24 小时。
