额度：别的 App 怎么做

2026-11-02 调研 · 用于决定 Keepline 额度条的数据来源和摆放位置 · 相关：额度条方向稿 · 摆放方向稿
结论
  • 同类终端工具本身没有额度条，全靠社区插件（列表里二十多个）。做法分两派：被动读本机记录，或者拿各家 CLI 的登录凭据调官方接口。
  • Keepline 现在（431a112a）属于被动派，做法和 status-ui-bar 几乎一样：Claude 截 statusline，Codex 读会话日志；Grok 读它自己的日志，这一点比那个插件还更不需要联网。
  • Codex 0.166 的 app-server 有 account/rateLimits/read，额度一变还会推送 account/rateLimits/updated。Keepline 已经连着这个服务，所以是最划算的升级：随时最新，Keepline 自己也不联网。
  • 值得抄的界面细节：倒计时直接写在百分比旁边（5h 35% 24m）；读数旧了打 *；点开弹层看全部窗口和缓存时间；额度挨着正在跑那个 Agent 的窗格显示。

本机核对过的事实

  • Claude Code 2.1.316：statusline 的输入里有 rate_limits.five_hour / seven_day {used_percentage, resets_at}；用 API key 或 Bedrock 登录时这里是 null。
  • Grok 1.0.70：~/.grok/logs/unified.jsonl 里每次启动记一条 creditUsagePercent、按周的 currentPeriod、subscriptionTier。之后几小时日志能多出几百 KB。
  • Cursor：~/.cursor 下没有任何额度记录。Qoder：只有每条回复的 usage.credits，没有总额。
  • Codex 0.166：app-server 提供 account/rateLimits/read、account/usage/read，并推送 account/rateLimits/updated。
  • 同类终端工具本体：程序里没有任何额度相关的代码。
