# 侧栏方向 B「任务线」可行性试验（2026-11-01）

**要支撑的决定**：侧栏是否采用方向 B（待办和会话合成一条任务线）。
**放弃条件**：用最近 7 天真实会话试归组，若大部分会话归不进「一件事」，或归出来的组不是一件事，放弃 B。

## 做法

对真实工作区数据库的只读副本，取最近 7 天、目录在 `~/Desktop/code/` 下的会话（454 个；Claude 287、Codex 164、Grok 3）。
分支来源：Claude 会话取日志里记录的 `gitBranch`（当时的分支）；Codex 日志不记分支，worktree 目录取它现在的分支，主仓库目录标为不确定。
归组规则：明确关联的待办优先；否则非 main 分支、来源可靠的按（仓库, 分支）归成一件事。

## 结果

| 项 | 数 |
|---|---|
| 明确挂到待办的会话 | 0 |
| 在 main 或没有 git / 目录已删 | 357（79%） |
| 能归成组（≥2 个会话）的分支 | 1 个，83 个会话 |
| 只有 1 个会话的分支 | 5 |

唯一的组是 keepline 的 `feat/sidebar-sessions`：一个长期分支，里面是十几个互不相关的话题（GPU 占用、复制粘贴、诊断页样式、skill 审查……），不是一件事。
大量会话是一次性的提问或排查，会话本身就是工作单位。

## 决定

**否定 B**。明确关联覆盖率为 0，按分支归组得出的组不对应「一件事」。侧栏采用方向 A（会话优先），任务线不做。
附带发现：会话标题多是用户第一句话（「你看看……」、一个链接），区分会话更该靠 A 的第二行（Agent 最后说的话 / 结果）和更好的会话命名，而不是归组。
重新考虑 B 的条件：你开始习惯先建待办再派给 Agent，且有一半以上会话挂在待办上。
