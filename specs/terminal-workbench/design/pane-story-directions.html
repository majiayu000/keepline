别家怎么做（2026-11-02 查）

cmux（libghostty 原生终端）：画面本身没有标题栏说明；Agent 要你时，画面外围亮一圈蓝环、侧栏那一格亮起；「最新一条通知文字」只写在侧栏每个工作区下面；Cmd+Shift+U 跳到最近未读。
Warp：状态是画面图标右下角的小徽标，只有五种：进行中、完成、出错、取消、卡住（等批准）；未读活动是行尾一个强调色圆点，聚焦后消失；完整信息放在悬停卡里，不截断。有人提过「卡住时给一个醒目的侧边提示」（#10242），没有回应就关了。
Superset / Conductor：状态放侧栏（进行中指示、完成提示音、Dock 角标），画面里是终端或对话本身，没有额外说明行。
Codex App：用户抱怨「等批准」很容易漏看，要求在线程列表里常驻一个等待状态，再加角标。
Claude Code agent view：每行 = 状态图标 + 会话名 + 一句话 + 时长。那一句由小模型生成：在干活时写在做什么，要你时写它问的问题（例「double jump or wall climb?」）。要你的排最上；终端标签标题写「2 awaiting input」。
Cursor Agents 窗口：侧栏按状态分组时有「Needs Attention」区（要批准、要回答、待看的计划、做完没看的）；通知措辞分开：「Done • 名字」「Input needed • …」「Approve terminal command」；悬停行出详情卡（路径、仓库、分支）。
Zed：等批准时，回合标签从「Generating」换成「Waiting for confirmation」；子 Agent 在等批准时，对话视图里冒出一条活动栏列出它们，点一下跳过去（理由：等的那个在屏幕外，看起来像卡住了）。线程侧栏按项目分组。
VS Code Agents 窗口：会话列表每行写状态和改动统计（+/− 行数），每个会话有自己的标题。
Crystal：屏幕边的竖条，每个会话一个颜色状态：工作中、等批准、完成。
Vibe Kanban：看板列 待办 / 进行中 / 待审 / 完成，「待审」= Agent 做完等人看，审在 diff 视图里。
tmux / Zellij 插件（workmux、claude-tmux-hop、tmux-claude-notifier、tmux-titles）：只在窗口名或标签标题前加一个图标（🤖 工作 / 💬 等你 / ✅ 完成），完成图标聚焦后自动清掉。
菜单栏小工具（claude-status-bar 等）：等权限是黄点；多个会话时优先显示等你的那个，不被「在想」的盖掉。
云端 Agent（Devin、Jules、Linear）：状态是固定枚举：等你输入、等批准、等计划确认、出错、完成。Linear 的状态由 Agent 最后一条活动自动推出来，开发者不手设。
共同点：查了 17 个，没有一家在画面标题下面常驻一行「任务 / 停在哪」。画面上只放状态（徽标、外圈、标签措辞）；一句话原因放在列表那一行；全文放悬停卡。唯一在画面内加条的是 Zed，而且只在有东西等你时才出现。
另一个发现：Claude 的那一句是生成的短句（它问的问题），不是回复原文第一行。我们现在的问题一半出在文字：拿回复原文第一行截断，读起来就乱。

对 Keepline 的意思：侧栏每行已经写了「停在 原因」，画面上再写一遍就是同一信息一屏两次。所以画面只需要让你知道「这个要你」（状态色 + 外圈），原因留在侧栏和悬停卡。见下面的 D′。
