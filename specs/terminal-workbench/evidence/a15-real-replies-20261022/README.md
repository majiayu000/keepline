# A15：“完成”自述分组的真实样本回归（2026-10-22）

**决定：采用 24b6aa7 的行首“完成+标点”规则，并把否定词检查收窄到匹配所在的那一句（_rules 6→7）。A15 的“声称完成”分组在真实日志上通过只读回归；在运行中工作台里重新分组的原生复看仍未做。**

## 方法

新增 [`claim_scan`](../../../../next/crates/keeplined/examples/claim_scan.rs)：用真实的 `keeplined::content::Parser`，只读解析本机 `~/.claude/projects/*/*.jsonl`（1671 个）和 `~/.codex/sessions/**/*.jsonl`（664 个），对每个文件输出最后回合状态、是否算“声称完成”、证据数，以及最后回复的首行。分别用 24b6aa7 之前、24b6aa7、本次三个版本各跑一遍，逐条比较。原始输出含用户对话内容，只留在本机临时目录，不进仓库；下面只记统计，以及少量改写后的短句。

## 结果

最后回合为 Completed 的会话约 1855 个（扫描期间日志仍在增长，三轮之间相差 2 个）。

| 版本 | 新增认作“声称完成” | 逐条核对 |
|---|---:|---|
| 24b6aa7（行首“完成”后可接标点和正文） | 14 | 全部是真正的完成自述，例如“完成。PR 已开好…”“完成，已验证。…”“完成:`…mp4`” |
| 本次（否定词只在同一句内生效） | 9 | 8 条是完成自述，例如“完成。…（另一可选项尚未实现）”“全部完成。…已提交”；1 条误判：单行 JSON 摘要正文里的“重做已完成的工作” |

漏判根因：旧逻辑只要整行出现“尚未 / 还没 / 未完成 …”，就把整行的完成自述作废；而真实回复常在后文另提其他未做的项。现在按 。！？；!?; 或“. ”分句，逗号不分句，因此“完成，但尚未测试”“已完成一半，还没提交”“Tests are not completed yet.”仍不算完成，已加进单测。

已知弱点：`已完成` 等短语出现在正文描述里时会被当作自述。这在改动前的 300 条已认出样本里本来就存在；本次让同类误判多了 1 条，出现在一个非交互的 JSON 输出会话上。
