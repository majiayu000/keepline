# 通知跳转：会话还没载入时点通知（2026-11-01）

要支撑的决定：旧 Tauri 菜单栏 App 的 #145（「后台服务没连上时点通知，目标不能丢」）已关闭未合并，next 工作台是否覆盖同类场景，覆盖不了就补上。放弃条件：next 已经覆盖，或修它需要动通知权限 / 真实投递。

## 结论：补上（采用）

核对：next 的系统通知由 App 自己发（`native.m`，`UNUserNotificationCenter`），点通知走 `navigate_to(session)`。会话不在当前工作区数据里时（后台刚重连、刚冷启动还没同步完），原来只写一句「会话尚未载入，请刷新工作台」就丢掉目标；而这句提示紧接着被 `request` 的 `begin_busy` 清掉，用户其实看不到。

现在：
- 记下目标和当时所在的页面，提示「会话还没载入，载入后自动打开」（先发请求再写提示，不再被清掉）。
- 每帧检查：会话载入了就打开它、清掉提示；用户在此之前自己换了页面（空间、标签、鸟瞰、待办详情任一变化）就放弃，以用户为准。新的一次点击覆盖旧目标。

## 证据

`route-e2e.py`：隔离 HOME，一条合成 Codex 日志，不调模型，不碰系统通知权限。原生场景 `KEEPLINE_ROUTE_EVIDENCE` 在窗口的数据副本里拿掉这个会话，再按点通知的路径调用 `navigate_to`：

- `waiting.png`：标签页上显示「会话还没载入，载入后自动打开」。
- `opened.png`：下一份工作区到达后自动进入鸟瞰并定位到这个会话，提示消失。
- `moved.png`：等待期间用户打开鸟瞰，会话载入后不再跳转。

连跑 3 次通过。反向验证：去掉每帧的检查，第二步失败（停在原页、提示一直挂着）。

## 没验

- 真实通知投递和点击（需要通知权限，等授权）；这里从 `navigate_to` 开始，不经过 `UNUserNotificationCenter`。
- 后台真的断开再重连的路径：本场景用「数据副本缺这个会话」模拟，到达方式同为下一份工作区。
- 冷启动时由点通知拉起 App：路由事件在窗口打开后才处理（`desktop::start` 的事件循环），这一点只读了代码。
