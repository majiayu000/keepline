## 过程中发现并修复的问题

第一次真实运行（[run1](run1-before-follow-fix.json)）四个场景都没绑定，也没有误绑定。根因：守护进程一直开着会话日志，FSEvents 在文件关闭前不报告追加内容，而 keeplined 只给已关联的日志挂 vnode 监听，结果未关联日志只读到创建时写的前两行，屏幕匹配拿不到原话。已离线复现：用一直打开的文件句柄分段写入，追加内容读不到；关闭句柄后才读到。

修复：存在未关联的托管 Codex 时，额外跟踪最近 10 分钟内、目录和这些终端相同、尚未关联的 Codex 日志，最多 16 个。测试夹具同步改成真实时序：TUI 启动时建日志、由终端外的进程一直开着、提示稍后追加。已确认旧代码在新夹具下失败、修复后通过。

第二次运行时 `/new` 失败，原因在驱动脚本：它把提示词里的 “ok” 当成回答已完成，在回合进行中就发了 `/new`，被 Codex 以 “disabled while a task is in progress” 拒绝。改为等界面出现 “Worked for” 后再发，第三次单独重跑 `/new` 通过。
