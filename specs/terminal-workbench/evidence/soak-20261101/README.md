# 两小时浸泡复测（2026-11-01）

要支撑的决定：今天 main（a4dc0803，含插件 hook、装饰、cd 跟随）长时间挂着会不会漏内存、漏 CPU、漏文件读写。放弃条件：两小时内 footprint 或 CPU 持续上涨，或 ps/lsof/日志/索引计数有变化。

**决定：采用（没有增长趋势）；绝对值偏高待验证。**

## 结果

脚本同 [acceptance-final/soak.py](../acceptance-final/soak.py)：release 构建，40 个外部会话加 8 个托管会话，HOME 和 runtime 都隔离，不启动模型。共 7200 秒，121 个样本。

| | 10-21 基线（锁屏） | 本次（屏幕亮着） |
|---|---|---|
| 客户端 footprint 起 / 止 / 峰 | 57.9 / 57.1 / 57.9 MiB | 506.6 / 114.9 / 506.7 MiB |
| 客户端累计 CPU | 0.12 s | 2.42 s（0.03%） |
| 后台 footprint 起 / 止 | 6.8 / 6.4 MiB | 15.0 / 6.6 MiB |
| 8 个 PTY | 不变 | 不变（约 1.4 MiB，CPU 0） |
| ps/lsof、目录枚举、日志、索引计数 | 首尾一致 | 首尾一致 |

趋势：客户端前 3 分钟 footprint 约 506 MiB，第 3 分钟降到 114.7 MiB。此后 117 分钟只多了 0.2 MiB，resident 从 130 MiB 降到 101.5 MiB 后保持不变。稳定后 CPU 两小时共涨约 0.9 秒。没有看到泄漏。

## 和基线不能直接比

`pmset -g log` 显示，这段时间 RustDesk 一直阻止显示器睡眠，所以屏幕是亮的，窗口在前台渲染。基线是锁屏后台驻留，两者条件不同。所以 114.9 MiB 对 57 MiB、2.4 秒对 0.12 秒，不能算回归，也不能算不回归。

## 没验

- 前 3 分钟的 506 MiB 峰值从哪来（推测是 GPU 首帧或字形缓存，没有拆开看）。
- 在锁屏条件下用今天的 main 重跑，和基线逐项比。
- 用户真实环境（非隔离 HOME、真实会话数量）。
