# 等你回答与新建待办：弹出还是让用户输入（调研 2026-10-21）

- 要支撑的决定：① Agent 等你回答（审批 / 选择题 / 等下一句）时，工作台弹卡片让用户点选项，还是带用户到终端里自己答；② 「＋ 新待办」用弹出表单还是一行快速输入。
- 放弃条件：如果 Keepline 拿不到结构化的等待事件（只能看屏幕文字猜），就不做终端外作答，只做提醒和跳转。
- 结论：**采用**（用户 2026-10-21 确认）。已写入 product.md 6.3 与 6.4「新建待办」。下面的指标作为验证。

## 1. 同类产品怎么做（证据摘要）

没有一家用强制弹出的模态框。分三种：

| 做法 | 产品 | 前提 |
|---|---|---|
| 只提醒，回到终端里答 | Herdr、cmux、Claude Squad、Agent Deck、Warp | 只能看屏幕或收 OSC 通知，没有结构化事件 |
| 聊天流里内嵌按钮作答 | Conductor、Superset、Vibe Kanban、Nimbalyst、Codex App、Cursor、VS Code、Zed（ACP）、Claude Code 桌面版 | 自己掌握 SDK / ACP / Hook 的结构化事件，不是在真实终端里 |
| 折中：提醒 + 快速回复，终端原生提示仍是准绳 | Claude Code agent view、crystl、ntfy 手机审批 | 提问可快速回复；**权限审批 Claude Code 官方也要求进会话处理** |

- Claude Code agent view：等待中的会话置顶黄色「Needs input」；选择题可在列表里按数字或自由输入快速回复；权限对话框不能快速回复，必须进入会话。https://code.claude.com/docs/en/agent-view
- Herdr 文档明确警告：状态判断错时，自动化会把字打进审批框。https://herdr.dev/llms-full.txt
- crystl：切走后才弹不抢焦点的浮卡，显示工具名、目标和变更预览；在终端里答也行。https://crystl.dev/docs/approval-modes/
- 终端外作答与终端脱节是实际存在的坑：手机上批准后主机提示不消失、Hook 与终端对话框竞速、终端答了 Hook 不取消（claude-code #12176、#15433、#79651，部分为镜像）。

新建任务：

| 做法 | 产品 |
|---|---|
| 快捷键唤出轻输入，标题/一句 prompt 必填，其余后补 | Linear `C`、Nimbalyst `⌘⇧I`、Things Quick Entry、Todoist 一行解析、Claude Squad `N` |
| 「建」与「建并开始」两个按钮 | Vibe Kanban（Create / Create & Start） |
| 长期上下文继承，不在每个任务里填 | Linear guidance、Copilot 指令文件、Devin Playbook |
| 没有任务对象，在终端里直接敲 | Superset、cmux、Herdr |

## 2. 用户痛点（按强度）

等待 / 审批：
1. 多会话下不知道哪个在等我，只能逐个切（claude-code #2654、#36885，HN 47765556）——最高频，用户反复自己造工具。
2. 「做完了还是卡住了」误判；通知该响不响、不该响乱响（#45781 等）。
3. 通知和审批疲劳导致盲批（Anthropic 称用户接受 93% 的权限提示）。
4. 想在通知 / 手机上审批，但要求写清具体命令、仓库、diff。
5. 终端外作答和终端状态不同步。
6. 选择题的「Other」自由输入体验差，用户常想自由回答。

新建 / 启动：
1. 想排队下一步，不想干等（#33323、#34835）——最强。
2. 排队或写到一半的 prompt 丢失。
3. 看板评价两极，偏好轻量记录或仓库里的 markdown。

反证：相当一部分用户明确偏好留在 tmux / 终端里答。

## 3. 对 Keepline 的建议

前提：Keepline 的画面就是真实终端，嵌在同一窗口里，「去终端答」只是一次点击，不是切 App。Claude 不装 Hook，Codex 也没有结构化审批事件给我们。

**等你回答：不弹模态，也不在终端外提交答案；把「找到它」和「答之前看清」做好。**

1. 识别优先：等你回答的会话在左栏「需要你」、标签、空间角标、菜单栏置顶；这是第一痛点。现有缺口：Claude 审批时 JSONL 没有记录，工作台显示「进行中」。补法按 Herdr 思路：只对已关联的 Agent 画面，在输出静止后检查画面底部是否匹配已知审批 / 选择题样式（严格规则，匹配不到就不标），作为日志信号之外的兜底；不逐帧解析。
2. 点「需要你」条目 / 通知 → 切到画面并聚焦，原生提示就在眼前，用户直接按 1 / 2 / 3 或输入。画面状态栏显示一行摘要（要批的命令或问题），「你在这里」卡显示上下文（仓库、命令、最近改了什么）。
3. 不做「同意」按钮，不模拟按键提交答案（与 6.3 现有约定一致）。理由：拿不到结构化事件，误判时会把字打进审批框；Claude Code 官方自己也不允许在会话外答权限对话框。
4. 通知降噪：只对等你回答和出错发，画面已聚焦时不发，同一事件只发一次，正文写清是哪个项目、要批什么。
5. 以后若接入结构化事件（例如用户自愿装 Hook），再考虑选择题的快速回复；权限审批仍进画面。

**新建待办：改成一行快速输入，表单作为「展开」。**

1. 「＋ 新待办」不弹整页表单，在左栏待办区顶部出现一行输入框：只填「要做什么」，项目默认当前空间，Agent 默认上次的选择；旁边两个按钮「保存」「保存并开始」，以及「展开」露出说明、验收标准、Agent 选择。首版不做快捷键，入口仍是可见按钮。
2. 验收标准不在记录时强制，点「开始」时如果为空，在预填说明行提示「还没写验收标准」并给「补写」入口，不阻止开始。
3. 补一条从会话反向生成待办的入口：会话卡上的「存为待办」用首条原话做标题（已有）。
4. 「排队下一步」是新建侧最强痛点：同一空间的待办列表天然就是队列；在待办行加「下一个」排序即可，不另做 prompt 队列（CLI 自己的排队行为不去替代）。

**验证指标与放弃条件**

- 指标：从「需要你」出现到用户在画面里作答的耗时；漏看的等待数（等待超过 10 分钟才处理的次数）；新待办从点「＋」到保存的耗时；验收标准填写率。
- 放弃 / 回调：如果改成一行输入后验收标准填写率明显下降、影响台账判断完成，就在「开始」前加一步轻量确认；如果画面底部兜底识别出现误标，收紧规则或关闭兜底，宁可漏标不误标。
