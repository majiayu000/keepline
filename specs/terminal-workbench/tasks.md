# Keepline 终端工作台实施与验收计划

状态：仅完成 Spec 草案，下面的实现与验收均未开始。2026-10-20 架构修订见 [tech.md 第 0 节](tech.md#0-2026-10-20-架构修订优先于本文其余部分)：P0 已由开源库测评（分支 `claude/terminal-eval-04a203`）完成大部分并终止；M1–M4 中 Tauri、WebView、xterm.js、Bun 常驻相关条目按第 0 节改写为 Rust 后台与 GPUI 客户端，未改写处以第 0 节为准。主规范：[product.md](product.md)，技术约定：[tech.md](tech.md)，产品定位与放弃条件：[产品卡](../product-card.md)。

## 1. 顺序与停止条件

```mermaid
flowchart LR
  P0[终端镜像与后台保活原型] --> M1[宿主协议与终端组件]
  M1 --> M2[App 内启动和切换]
  M2 --> M3[任务 / 账本 / 提醒闭环]
  M3 --> M4[故障 / 性能 / 原生验收]
  M4 --> Release[用户决定正式发布]
```

一次只推进一个可独立验证的阶段。不得为了终端工作台同时开始 TUI、AppKit/Metal、SSH、全量 Rust 数据迁移或 Remem 接入。只有任务中的实测与验收完成才勾选，不将文档中的接口视为已实现。

## 2. P0：先证明最高风险的两个选择

> **已由开源库测评取代并终止（2026-10-20）**：VT 库、快照、kl-relay 与 1/4 画面资源已有数据；未完成项（中文输入法、Ghostty 4 分屏基准、GPU 与耗电、延迟、打包 App 生命周期）移入 M1–M4 的首个实现验收。以下保留为历史计划。


### P0.1 终端显示镜像原型

- [ ] 在现有 Rust PTY 原型上补最小权威状态导出，固定 alacritty 与 xterm 版本。
- [ ] 做一个实验面板，先单终端、再同一页 4 个终端同时可见，只验证从模型导出的显示序列；不改现有产品导航。
- [ ] 4 个可见终端各 100 KiB/s 输出时测帧耗时、CPU 与聚焦画面输入延迟；切换焦点时输入不串画面；再加 36 个只在 Rust 侧解析的后台会话测总资源。
- [ ] 对正常屏/备用屏、光标末列与 wrap-pending、样式、宽字符、组合字符、emoji、滚动区及跨读块的转义序列建立 fixture。
- [ ] 验证应用光标键、keypad、bracketed paste、鼠标及两种 CLI 实际启用的键盘/焦点模式。
- [ ] 输出设备状态查询时，只有 Rust 回复；浏览器侧不再发送协议回复。
- [ ] 快照后继续增量输出、输入、resize，与未断开的参照终端行为一致。
- [ ] 单快照超过 1 MiB 的分块恢复完整；不能只比较文本或 checksum。
- [ ] 用真实 Codex 与 Claude Code 操作菜单、中文输入、审批和中断，记录 CLI/OS/组件版本与结果。

**通过条件**：两种真实 CLI 与所有 fixture 均能输入并正确恢复状态；没有重复设备回复、输入模式错位或 Unicode 截断。原型失败就修订 tech.md 的 D03，再评估；不扩大成多渲染器架构。

### P0.2 打包 App 退出后的宿主存活

- [ ] 使用隔离运行目录启动最小打包 App 与真实宿主，验证宿主独立于 sidecar/父 stdin。
- [ ] 关闭窗口、正常退出 App、kill App、重新打开；终端 ID/PID 保持，输出持续。
- [ ] Bun 业务服务重启，终端保持；App 可重新连接并恢复画面。
- [ ] 宿主主动退出/被杀后，不把新实例当成旧 PTY；不给用户虚假可输入状态。

**通过条件**：实际 `.app` 的生命周期有进程、PTY 和画面证据，不能用浏览器模拟 IPC 替代。

### P0 交付物

一个最小可运行原型、固定版本、风险实验报告和必要的 Spec 修订。此阶段可以用合成 echo 程序，不自动替换安装版、不修改用户 Hook 或凭证。

## 3. M1：完善终端宿主和显示契约

- [ ] major 1 hello/list/launch/attach/控制权/input/resize/ack/detach/stop 与 lifecycle 协议。
- [ ] 宿主实例 ID、启动去重、intent 写入顺序、启动失败清理与崩溃后禁止自动重放。
- [ ] 完整快照、连续显示增量、跳号 resync、分块、慢消费者与资源回收。
- [ ] 部分 PTY 写入和输入回执；确认丢失时不能自动重放。
- [ ] 一终端一写租约，明确接管后旧 generation 失效，缩放遵循同一控制权。
- [ ] PTY/进程组、正常退出排空、主进程退出但后代持有 FD、停止与强制停止。
- [ ] 最近 5,000 行滚动缓存与结束画面持久化；切换页面、关闭窗口不终止进程，关闭画面或标签会停止终端。
- [ ] GPUI 客户端与后台的 Unix socket 连接，同 UID 校验；只有授权客户端可以写入（取代原 Tauri bridge 条目）。
- [ ] GPUI 空闲补丁（无变化时暂停显示链接）与锁定的 gpui 发行线；libghostty-vt 锁 commit 与 Zig 构建。

**放行**：协议/PTY 针对性测试、Rust fmt/clippy、真实 WebKit 单终端输出/输入通过；仅在改动涉及现有业务 TypeScript 时增加对应类型检查。测试不得杀同名的用户 Agent。

## 4. M2：完成 App 内的日常交互

- [ ] 工作视图：空间列表与「需要你」短列表的精简左栏、每个空间的标签行与需要你角标、每个标签 1–4 画面的规则网格、画面状态栏、按需弹出的「你在这里」卡；复用现有视觉设计。
- [ ] 鸟瞰视图：按分组铺卡片、「新」标记、空间筛选、折叠计数与逐个清理入口；离开超过设定时长后默认打开；点卡片切到正确的空间、标签和画面。
- [ ] 新画面与预填命令：「＋」、分屏、空位、「开始」「继续」统一走「开 shell + bracketed paste 预填、不带回车」；待办说明与续接提示正确转义；CLI 路径与 GUI 登录环境。
- [ ] CLI 缺失、未登录、目录信任、启动失败的准确状态；不自动安装或更改登录。
- [ ] 多会话与画面切换、焦点、滚动位置；只绘制当前标签可见画面；重新分组不切换当前标签和聚焦画面；首版不设应用快捷键，键盘输入只进入聚焦画面（复制粘贴除外）。
- [ ] 中文 IME、复制、多行及大粘贴、搜索、鼠标模式与尺寸变化。
- [ ] 第二窗口只读/明确接管，重连时恢复画面完成前不开放输入。
- [ ] 关闭标签、红色关闭按钮、退出继续运行、退出停止的产品行为。
- [ ] 初始历史扫描期间可以启动和操作终端；错误不能变成永久加载骨架。

**放行**：A01–A07、A11 中的 UI 自动化与两种真实 CLI 人工交互通过。模拟 API 的浏览器测试只覆盖 UI 行为，不能替代 PTY 链路。

## 5. M3：连接原有产品价值

- [ ] 一张终端关联表，保留原 CLI session 身份、terminalId、operationId 与续接关系。
- [ ] 待办：新建表单、待办的标签与信息条、空位「再开一个会话」、左栏与鸟瞰的待办、待办详情；按 product.md 4.3 实现会话归属与摆放分离（挂到待办 / 取消关联、标签命名、关标签不停会话并可恢复布局）；复用现有派发 ID 去重，重复「开始」不开重复画面。
- [ ] 终端先可用、会话后关联；无法唯一匹配时保留未关联，不猜测错绑。
- [ ] 托管进程状态优先使用宿主事实，外部会话仍使用已有观测与 unknown 语义。
- [ ] 审批、结构化问题与待核对提醒能够一键定位正确托管终端。
- [ ] 外部会话正确显示来源；运行/未知时不一键复制执行，明确退出后才允许 CLI 恢复。
- [ ] 已退出托管会话通过已有恢复命令创建新终端，任务/账本续接关系正确。
- [ ] 会话结局（已完成、暂存、已放弃）的持久化、撤销与新回合重新打开；暂存到期与「很久没动」分组及逐个清理入口。
- [ ] 「你在这里」卡四个字段按回合更新，「做成了」只取机械证据；无法提取时显示「无」，不由模型补写证据。
- [ ] 账本、待办、目标、回顾、用量为伴随视图，终端输出不触发每块账本重算。
- [ ] App 默认工作路径不再依赖 AppleScript 外部终端自动化；相关文案与入口同步。

**放行**：A08–A09、A12、A15–A17、A19、原有任务/账本回归及同项目并发身份测试通过。若窗口被关闭，任务状态不会自动完成或丢失。

- [ ] 恶意终端标题/链接/控制序列、普通浏览器和非授权窗口调用写接口的拒绝测试。
- [ ] Finder 启动真实 App，用两种原生 CLI 各完成启动、对话、审批、退出后重开和 resume。
- [ ] 通知实际展示与点击、菜单栏定位、退出菜单、登录环境、键盘无障碍人工验收。

- [ ] README、桌面安装说明和验证报告同步；明确源代码、测试包、安装版和正式发布状态。

## 7. 验收矩阵

| 类别 | 自动验证 | 真实原生验证 | 产品条目 |
|---|---|---|---|
| 启动与身份 | launch 去重、关联、同 cwd 并发、子 Agent | Codex/Claude 实际 session 关联 | A01、A02、A08 |
| 终端交互 | ANSI/Unicode/两屏/模式 fixture、输入回执 | IME、粘贴、原生审批与菜单 | A03–A05 |
| 后台与恢复 | 断连、租约、宿主实例、EOF | 退出/kill App、重开、CLI resume | A06、A07、A10–A12 |
| 工作闭环 | 任务、证据、验收与通知路由回归；分组与结局状态转换；鸟瞰跳转到空间 / 标签 / 画面 | 通知展示、点击、聚焦；真实会话的「你在这里」卡与状态栏抽查；离开后回来的鸟瞰 | A08、A09、A15–A17、A19 |
| 权限与输出隔离 | socket UID、capability、输出不执行 | 普通浏览器不可写、链接/剪贴板 | A13 |
| 性能与资源 | 固定负载、累计 CPU、队列/FD/RSS | WebKit 实际绘制、24h 驻留 | A14 |

退出码 0、可见终端文本、API 返回 200、构建成功都不能单独证明整个交互闭环。真实模型调用可能产生费用，实施时先使用合成程序；真实运行时验收遵循届时用户授权和本机登录状态。

## 8. 发布与操作边界

本次只交付 Spec。后续实现默认使用隔离数据目录和测试包，保留既有安装版与原始 Agent 记录。修改 `.env`、API key 或用户 Hook 需要相应明确授权。

正式签名、公证、推送、合并、发布与替换用户安装版按用户的具体授权执行，不能由「Spec 完成」推导出这些授权。

## 9. 评审要点

以下是可评审的设计选择，默认按本文推进研究和实现，不要求用户替工程团队选择协议细节：

1. App 作为主入口；日常是空间 + 标签 + 2–4 画面分屏的工作视图，回来时先看按分组铺卡片的鸟瞰视图；左栏只有空间和「需要你」短列表，「你在这里」卡按需弹出。
2. 首版同时支持 Codex 与 Claude Code；分屏只做每标签 1–4 画面的规则网格，不做自由拖拽布局。
3. 常驻部分全部进 Rust 后台（libghostty-vt + 自写协议），界面为 GPUI 客户端；Bun 服务不再常驻（2026-10-20 修订，原「复用 Bun 业务服务、不整库重写」作废）。
4. 外部会话保持观察；停止后通过 CLI 恢复进入 App，不能伪装成接管现有外部 PTY。
5. App 退出后任务可继续，但系统重启/宿主死亡只承诺原 CLI 能力范围内的恢复。

其中第 3 项的渲染镜像方案须以 P0 结果放行；这是明确的工程风险，不是已验证结论。其余需求若用户调整，应同步修改产品、接口和验收矩阵。
