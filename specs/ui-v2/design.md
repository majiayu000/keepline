# Keepline UI v2

主视觉来源：用户提供的 `库的UI设计需求.zip`，以 `Keepline App v2.dc.html` 为主，`Agent Panel.dc.html` 为完整进度账详情参考。旧 App、Task Board 和线框补充交互；不把设计稿演示数据作为产品数据。

## 实现边界

- 保持现有 HTTP API、错误响应、证据与人工验收语义。保留会话恢复、要求确认／编辑、步骤纠正／规则、约束、目标归属、导入要求、后续建议、任务派发、回顾导出和原有辅助页面。
- 220px 主侧栏，56px 顶栏，24px 主边距，12px 卡片圆角，440px 详情抽屉；完整进度账使用 Agent Panel 的 300px 侧栏。桌面尺寸按原稿，窄屏补充响应式。
- 数据请求在 `services/ledger.ts`；刷新、订阅与 mutation 在 `hooks/useLedger.ts`；文字、状态与分组派生在 `pages/ledger/presentation.ts`；页面协调在 `LedgerPage.tsx`；各视图与编辑器按职责拆为组件，CSS module 控制界面样式。复用现有认证、session API、WebSocket 和原有 hooks。
- 稿件中的状态、上下文百分比和恢复命令必须有真实数据依据。上下文 API 没有百分比时显示未知；恢复命令由现有后端生成。人工确认前候选要求不计入进度。

## 验证

类型检查与生产构建；现有进度账契约测试；浏览器验证布局切换、项目／搜索过滤、抽屉、完整详情、编辑、验收、派发预览、设置、回顾、错误与窄屏。用相同浏览器和字体，在一致视口／数据下对照原稿截图及元素尺寸，记录覆盖范围和差异。
